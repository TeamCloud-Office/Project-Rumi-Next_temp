# Project-Rumi-Next

Iris와 연동해 카카오톡 메시지를 처리하는 Node.js 챗봇입니다. 계정·채널 관리, 스타 송금, 출석·게임, 날씨·음악·사전, 운영자 명령, 입퇴장 이벤트와 대화 기능을 제공하며 사용자·채널·기록 데이터는 SQLite 파일로 관리합니다.

현재 버전은 `0.1.0`이며 개발 중입니다. 이 문서는 현재 등록된 명령과 실행 가능한 서버를 기준으로 설명합니다.

## 요구 환경

- Node.js 20 이상 및 npm
- HTTP API와 메시지 웹훅을 사용할 수 있는 Iris 서버
- 데이터 디렉터리에 대한 읽기·쓰기 권한
- Next에서 Iris API에, Iris에서 Next 웹훅에 접근할 수 있는 네트워크 구성

주요 의존성은 Express, dotenv, json-bigint, sql.js입니다.

## 설치 및 실행

프로젝트 루트에서 의존성을 설치합니다.

```sh
npm ci
```

`.env.example`을 `.env`로 복사합니다. 기존 `.env`가 있으면 해당 파일을 편집합니다.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux/macOS:

```sh
cp .env.example .env
```

실행 환경에 맞게 `.env`의 주소와 포트를 설정한 후 시작합니다.

```sh
npm start
```

시작점은 `src/Main.js`입니다. 서버가 시작되면 웹훅 수신 주소와 Iris API 주소가 콘솔에 표시됩니다. `Ctrl+C` 또는 `SIGTERM`으로 종료할 수 있습니다.

## 환경 설정

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `HOST` | `172.17.0.1` | Next 서버가 수신할 로컬 인터페이스 주소 |
| `PORT` | `2907` | Next 웹훅 수신 포트 |
| `IRIS_BASE_URL` | `http://127.0.0.1:3000` | Next에서 호출할 Iris API 주소 |
| `IRIS_TIMEOUT_MS` | `10000` | Iris 요청 제한 시간, 밀리초 |
| `RUMI_DATA_PATH` | 프로젝트의 `data` 디렉터리 | 데이터 저장 루트 경로 |
| `DEV_CHANNEL_ID` | `18375965161587381` | 채팅방 등록 신청을 전달받을 운영 채널 ID |
| `WATCHER_INTERVAL_MS` | `60000` | 역할·프로필·대여 알림 확인 주기 |
| `ENABLE_EVAL` | `false` | 예약된 개발용 eval 명령 감지 여부. 임의 코드는 실행하지 않음 |

`HOST` 기본값은 Docker 게이트웨이 주소를 사용하는 구성을 전제로 합니다. 해당 주소가 없는 환경에서는 실제 로컬 주소로 변경해야 합니다. 같은 컴퓨터 안에서만 접근하는 예시는 다음과 같습니다.

```env
HOST=127.0.0.1
PORT=2907
IRIS_BASE_URL=http://127.0.0.1:3000
IRIS_TIMEOUT_MS=10000
```

Iris가 다른 컴퓨터나 컨테이너에 있다면 그 환경에서 접근할 수 있는 Next 주소를 사용해야 합니다. `HOST=0.0.0.0`은 모든 IPv4 인터페이스에서 수신한다는 뜻이며 웹훅 목적지 주소로 사용하지 않습니다.

현재 `RUMI_DATA_PATH`는 `.env` 로딩 전에 읽힙니다. 데이터 경로를 바꾸려면 실행 전 프로세스 환경변수로 지정합니다.

```powershell
# Windows PowerShell
$env:RUMI_DATA_PATH = 'D:\RumiData'
npm start
```

```sh
# Linux/macOS
RUMI_DATA_PATH=/srv/rumi-data npm start
```

## Iris 연결

통신 방향에 따라 두 주소를 각각 설정합니다.

| 방향 | 설정 또는 경로 | 역할 |
| --- | --- | --- |
| Next → Iris | `IRIS_BASE_URL`의 `/query`, `/reply` | 메시지 조회 및 응답 전송 |
| Iris → Next | `http://<Iris에서 접근 가능한 Next 주소>:2907/message` | 메시지 이벤트 전달 |

Iris의 웹훅 목적지를 Next의 `POST /message`로 지정합니다. `IRIS_BASE_URL`을 설정해도 Iris의 웹훅 목적지가 자동 등록되지는 않습니다.

연결 후 카카오톡에서 다음 명령으로 응답을 확인합니다.

```text
루미야 핑
```

정상 응답은 `퐁!`입니다. HTTP 수신만 확인하려면 실제 Next 주소로 다음 요청을 보낼 수 있습니다.

```sh
curl -X POST http://127.0.0.1:2907/message -H "Content-Type: application/json" -d '{"type":0}'
```

이 요청의 예상 응답은 `{"ok":true}`이며 카카오톡 메시지를 전송하지 않습니다. Iris 연결과 응답 전송까지 확인하는 검사는 아닙니다.

현재 웹훅은 텍스트 메시지 처리 중심이며, 큰 숫자 ID는 문자열로 보존합니다. 별도의 웹훅 인증 검사는 구현되어 있지 않으므로 수신 포트는 Iris가 접근하는 네트워크 범위로 제한해서 운영합니다.

| 닉네임 기록 | `루미야 사용자 닉네임 기록` | 방장이 닉네임 변경 이력 조회 |

사용자 정보는 채널별로 관리되며, 일반 메시지 처리 시 사용자가 없으면 자동 생성됩니다. 동명이인 검색 결과에는 공개 ID가 표시됩니다. 송금 대상을 명확하게 지정하려면 공개 ID를 사용합니다.

송금은 한국 시간 기준 07:00 이상 22:00 미만에 가능하며 한 번에 1~99,999,999스타를 보낼 수 있습니다. 자기 자신에게 보내거나 잔액을 초과하는 송금은 거부합니다.

출석은 한국 시간 기준 하루 한 번 100스타를 지급하고, 채널별 당일 순위·누적 출석·1등 횟수를 저장합니다. `출석 체크`, `출석명단`, `내출석` 별칭도 지원합니다.

레거시 도박은 흑/백(각 50%) 또는 0~4(각 20%)를 선택합니다. 승리 시 베팅 원금을 제외한 순이익은 흑백 1배, 숫자 3배이며, 패배하면 베팅액을 잃습니다. `도박 흑 100`, `흑에 100스타 도박해줘` 형식을 지원합니다. 기존 간편 명령 `도박 100`은 45% 확률로 베팅액만큼 얻는 방식입니다.

숫자야구는 서로 다른 숫자 세 자리를 사용하며 정답을 맞히면 게임 상태를 제거합니다. 게임 상태는 메모리에 있어 프로세스를 재시작하면 사라집니다.

### 채널 기능 상태

송금·출석·도박·숫자야구는 채널의 대여 상태와 해당 기능 설정이 활성화되어 있어야 실행됩니다. 비활성 상태에서는 응답하지 않습니다.

| 기능 | 저장된 기능 키 |
| --- | --- |
| 송금 | `remittance` |
| 출석 | `attendance` |
| 도박 | `gambling` |
| 숫자야구 | `numGame` |
| 베라31 | `bera` |
| 주식 | `stock` |
| 끝말잇기 | `word` |

새 채널은 `state: 0`이고 모든 기능이 비활성입니다. 방장이 등록 신청을 보내면 사이트 관리자가 `루미야 방 등록 {채널 ID} {일수}` 명령으로 대여를 시작할 수 있습니다. 등록된 방에서는 방장이 `루미야 {기능} 기능 켜줘/꺼줘`로 기능을 변경합니다. 대여 기간이 만료되면 상태가 자동으로 비활성화됩니다.

### 사이트 관리자 명령

사용자 데이터의 `admin` 값이 활성화된 계정만 사용할 수 있습니다.

| 기능 | 입력 예시 |
| --- | --- |
| 전체 공지 | `루미야 공지 점검 안내` |
| 채널 ID | `루미야 채널 ID` |
| 채널별 전체 스타 순위 | `루미야 스타 랭킹 123456` |
| 관리자 설정 | `루미야 관리자 123456 USER_ID true` |
| 밴 설정 | `루미야 밴 123456 USER_ID true 사유` |
| 경고 설정 | `루미야 경고 123456 USER_ID 3` |
| 대여 등록 | `루미야 방 등록 123456 30` |
| 스타 조정 | `루미야 스타 123456 USER_ID +100` |
| 사용자·채널 목록 | `루미야 사용자 목록 123456`, `루미야 채널 목록` |
| 명령 기록 | `루미야 명령어 기록 123456 USER_ID` |

채팅을 통한 임의 JavaScript 실행은 보안상 지원하지 않습니다.

## 데이터와 기록

| 기본 경로 | 저장 내용 |
| --- | --- |
| `data/users/UserData.db` | 채널별 사용자 정보·스타·인벤토리 |
| `data/users/UserJLLog.db` | 사용자별 채팅 및 명령 기록 |
| `data/channels/ChannelJLLog.db` | 채널 정보·대여 상태·기능 설정 |
| `data/users/games/AttendanceData.db` | 출석 목록과 개인 통계 |
| `data/db/Message.db` | 호출어 대화 문장과 조건 |
| `data/db/MagicAnswer.json` | 마법의 루미 답변 목록 |

DB 접근 시 필요한 테이블과 누락 컬럼을 생성합니다. 명령 기록은 사용자별 최근 200개, 한 명령의 응답은 앞 3개까지 보관하며 명령 설명과 각 응답은 500자로 제한합니다. 일반 채팅은 최초·최근 메시지와 횟수를 기록합니다.

`.env`, `config/private.json`, `data/`는 Git 추적에서 제외됩니다. 설정과 데이터는 배포 시 별도로 준비하고 백업해야 합니다.

같은 SQLite 파일을 사용하는 테이블은 하나의 메모리 DB를 공유하고 파일 쓰기는 순서대로 처리됩니다. 단일 프로세스 운영을 전제로 하며, 송금처럼 여러 행을 연속으로 바꾸는 작업은 완전한 SQLite 트랜잭션이 아니므로 다중 프로세스에서 같은 데이터 파일을 동시에 열지 않아야 합니다.

한국어기초사전은 `config/private.json`의 `KRDICT_API_KEY`가 필요합니다. `config/private.example.json`을 참고하세요. 외부 검색 서비스의 응답 형식이나 네트워크 상태에 따라 날씨·음악·사전 명령만 실패할 수 있습니다.

## 프로젝트 구조

```text
src/
  Main.js          프로그램 시작 및 종료 처리
  bootstrap/       의존성 구성과 명령·이벤트·라우트 등록
  core/            Bot, 이벤트, 명령 관리 및 Context 생성
  commands/        채팅 입력 판별 및 명령 실행
  services/        사용자·채널·게임 등의 업무 처리
  presenters/      응답 문장 변환
  integrations/    Iris 등 외부 서비스 연결
  http/            Express 서버, 웹훅 라우트, 미들웨어
  database/        SQLite 접근, 스키마, Repository
  config/          환경변수, 기본값, 데이터 경로
scripts/           데이터 점검 등 실행 도구
tests/             테스트
docs/              상세 문서
data/              실행 데이터, Git 제외
```

명령은 `src/bootstrap/registerCommands.js`의 목록에 등록합니다. 명령 파일은 `name`, `matches(ctx)`, `execute(ctx)`를 제공하고 `ctx.send(text)`로 응답합니다.

레거시에서 비활성 상태였던 주식·베라31·끝말잇기는 Next로 옮겼지만 새 채널에서 기본값은 꺼짐이며, 방장이 필요한 기능만 활성화해야 합니다. 끝말잇기는 한국어기초사전 API 키가 필요합니다.

## 개발 및 점검

| 명령 | 동작 |
| --- | --- |
| `npm start` | 웹훅 서버 실행 |
| `npm test` | Node.js 테스트 실행 |
| `npm run check:data` | 지정된 DB 7개의 존재 여부·테이블·행 수 출력 |

데이터 점검 명령은 DB를 수정하지 않습니다. 테스트는 Iris 응답·큰 ID·timeout·종료, 계정·출석·송금, 대여·방장 권한·기능 변경·동명이인 선택·멤버 이벤트와 다중 테이블 데이터 보존을 확인합니다. 외부 서비스의 실제 응답과 운영 Iris DB 구조는 배포 환경에서 별도로 확인해야 합니다.

테스트의 기본 DB 접근을 운영 데이터와 분리하려면, 예를 들어 PowerShell에서 실행 전에 임시 경로를 지정합니다.

```powershell
$env:RUMI_DATA_PATH = Join-Path ([System.IO.Path]::GetTempPath()) ('rumi-next-tests-' + [guid]::NewGuid().ToString('N'))
npm test
```

이 설정은 현재 셸에 유지됩니다. 실제 서버는 운영 데이터 경로를 설정한 별도 셸에서 실행합니다.

PM2가 설치된 환경에서는 저장소의 단일 프로세스 설정을 사용할 수 있습니다.

```sh
pm2 start ecosystem.config.cjs
pm2 logs rumi-next
```

연결 문제와 주소별 점검 방법은 [Iris 연결 문제 해결](docs/Iris-Troubleshooting.md)을 참고하세요.
